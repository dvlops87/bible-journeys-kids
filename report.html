01 — CONCEPT

What it is

The Shepherd King turns the David and Goliath narrative into a short interactive game rather than a static retelling. The player moves through David's arc — shepherd, court musician, reluctant champion — making small character choices, then plays out the duel itself as a real physics minigame: draw back a slingshot, judge the angle and power, and try to land a stone on Goliath's forehead before the five stones from the brook run out.

The build carries one explicit constraint throughout: dramatize freely between the verses, but never rewrite what the verses themselves say — the "what if" branches described in §4 exist specifically to keep that line visible rather than blurred.

03 — THE DUEL MECHANIC

A physics problem, not a quick-time event

The slingshot is a real (if simplified) projectile-motion simulation: pull direction and distance set launch velocity, gravity is applied every frame, and a hit is only scored if the stone's arc actually intersects Goliath's forehead — a smaller, harder target than his body. This was also the game's main source of bugs during development (see §5).

Two input paths

Drag-to-aim for pointer/touch; focus the canvas and use arrow keys (angle/power) plus Enter or Space for keyboard-only play — added after the first accessibility review flagged the duel as the one control excluded from keyboard use.

Screen-size-adaptive throw

Every visual size (Goliath, the sling, the stone) stays fixed in pixels. Only the launch speed is recalculated from the live geometry — distance to Goliath and the fixed height gain — so a full pull reaches him at any canvas width, narrow phone to wide desktop.

04 — PARALLEL TIMELINES

Wrong choices lead somewhere, not nowhere

Three of the decision scenes carry a fourth, riskier option beyond the canon ones. Choosing it doesn't end the game — it opens a short, clearly-labeled "what if" detour, then returns the player to the same fork to choose again. Each detour is visually marked (a violet rule, an explicit "Parallel Timeline" tag, and an in-text disclaimer) so it is never mistaken for the scriptural account.

07 — TECHNICAL NOTES

How it's built

No dependencies

One HTML file: inline CSS and vanilla JS in a single IIFE. No framework, no build step, no external libraries — the canvas duel is hand-rolled 2D physics.

Persistence

localStorage remembers the player's best duel result (fewest stones to a kill) and their chosen language across visits — no server, no account.

Theme

Deliberately single-theme (night sky, bronze accent) rather than light/dark-adaptive — a stylistic choice matching the "shepherd under the stars" motif that runs through the source material.

Accessibility baseline

Keyboard-operable throughout, prefers-reduced-motion respected, WCAG-AA-level contrast on the shipped palette, ARIA label on the one canvas-based control.
